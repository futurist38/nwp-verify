# 예보변화 수집 캐시 개선 (2026-11-10)

기존에는 `verification/fcstdiff/`가 Git 저장 대상에서 제외되어 실행마다
어제 17시·오늘 05시 발표의 97지점씩을 다시 받았다. 실행
`42760431162`에서 194건 수집에 543.15초가 걸렸다.

- 시간별 기온 캐시를 main에 보관하고 다음 실행에서 그대로 읽는다.
- 오래된 커밋에서 시작한 대기·재실행 작업도 수집 직전에 최신 main의 캐시만
  복원한다. 실행 중인 소스와 다른 검증 이력은 교체하지 않는다.
- 대상일 24시간의 유효한 값이 모두 있는 지점은 API 호출을 생략한다.
  빈 자료·누락 시간·비정상 값이 있는 지점만 다시 요청한다.
- 지점 수신 성공마다 임시 파일을 쓴 뒤 원자적으로 교체한다. 수집 단계
  직후 캐시를 main에 저장하고, 마지막 검증 저장에서도 다시 반영한다.
- 캐시는 오늘을 포함해 최근 4일만 유지한다. 오래된 실행이 만료된 캐시를
  되살리지 못하도록 저장 시점에도 정리한다. 다른 검증 이력은 삭제하지 않는다.
- 어제 17시→오늘 05시 비교, 내일 대상, 계산에 필요한 최소 20시간 조건은
  유지한다. 24시간은 재수집을 생략할 캐시의 완전성 기준이다.
- 결측 지점은 표출 JSON에서 제외하고 NaN을 기록하지 않는다.
- 재사용·조회·수신·미완료 지점 수와 처리시간을 로그로 남긴다.

`python plot_fcstdiff.py --issue YYYYMMDD05 --no-plot --cache-only`는 API와
인증키를 사용하지 않고 캐시를 검사하고 결과를 재생성한다. 필요한 지점의
시간 자료가 부족하면 실패하여 운영 자료를 추가로 조회하지 않는다.

검증은 194건의 두 발표 재사용, 부분 수신 재시도, 잘못된 캐시·NaN 처리,
중단 시 이미 받은 자료 보존, 원자적 교체 실패, 4일 경계, 기존 계산과의
일치, 실제 Git 저장 후 새 체크아웃의 무호출 재사용을 포함한다.

하루 첫 수집에는 기존 API 수신시간이 필요하다. 같은 비교 짝이 완성된 뒤
반복 실행에서는 API 요청이 0건이 되며, 파일 읽기와 계산만 수행한다.
